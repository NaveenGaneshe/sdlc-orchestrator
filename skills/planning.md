# Planning skill

## Apply when

A request changes behavior, architecture, interfaces, or coordination across components or teams.

## Instructions

1. Read [`memory/constitution.md`](../memory/constitution.md); do not bypass its checkpoints.
2. **Explore:** Inspect relevant code, tests, decisions, owners, and dependencies. State unknowns rather than guessing.
3. Create or refine the numbered feature's `spec.md`. Keep the problem and acceptance criteria solution-neutral.
4. Stop for the specification checkpoint.
5. **Codify:** Use [`templates/plan-template.md`](../templates/plan-template.md) and [`templates/tasks-template.md`](../templates/tasks-template.md). Prefer the smallest sufficient design; record alternatives only when they informed a decision.
6. Give every task an owner, status, dependency, and verification step. Update `ownership.md` for cross-team work.
7. Stop for the plan checkpoint. Enter **Commit** only after approval.

## Output

Produce reviewable spec, plan, task, and ownership artifacts—not an implementation disguised as a plan.
