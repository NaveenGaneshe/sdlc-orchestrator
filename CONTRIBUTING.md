# Contributing

1. Read and follow the [`memory/constitution.md`](memory/constitution.md).
2. For a material change, create a numbered workspace with `./scripts/new-feature.sh feature-name`.
3. Complete and review the specification before planning; complete the plan, tasks, and ownership records before implementation.
4. Implement the smallest approved change test-first, keeping task and dependency status current.
5. Submit focused changes with verification evidence and links to the relevant acceptance criteria.

Small documentation corrections may use a lightweight spec, but they still follow the ECC sequence: inspect context, state the intended correction, then make and review it.
